# Northstar — Goal Monitor MVP

本地运行的个人目标监控 dashboard，把长期方向连接到年度里程碑、30 天项目、每周检查点和每日行动。

## 本地启动

```bash
npm install
npm run dev
```

打开终端显示的本地地址。生产构建：`npm run build`；测试：`npm test`。

## GitHub Pages 部署

推送到 `main` 分支后，GitHub Actions 会运行测试、构建并发布到 GitHub Pages。项目页地址为 `https://hiworld121212-boop.github.io/goal-monitor/`。首次创建仓库后，在仓库 Settings → Pages 中将 Build and deployment source 设为 GitHub Actions。

## 当前包含

- 目标地图：五年方向 → 年度里程碑 → 30 天项目 → 每周检查点。
- 多目标工作区：可分别管理职业、财务、健康等方向；每个目标的行动、结果指标和复盘相互隔离，可随时切换。
- 多目标今日总览：在首页查看其他目标今天的已排期行动，直接开始、确认完成或跳转到对应目标；状态更新只写入该目标。
- 周投入预算：可自定每周专注分钟预算，首页汇总所有目标本周已排期时长并提示超量；这是排期估算，不会自动改期或视为实际用时。
- 全目标周日历：集中查看各目标已排期行动；专注提醒会标注目标来源，ICS 导出包含全部目标并在事件标题标明目标。
- 日历行动执行：可以从周议程开始、确认、跳过或恢复行动；确认时可记下证据说明，跳过项留在议程中便于恢复，但不会导入 ICS。
- 今日行动：杠杆任务、完成标准、计划专注时间和证据状态。
- 用户明确确认后才会把任务记为“已确认”；计划时间不等于成果。
- 日终回顾、每周复盘、双周检查和月末项目决策，可保存到本机。
- 每周复盘可把用户写下的下一步显式加入行动列表；需要填写完成标准，可选排期，计划状态不会自动计为成果。
- 导出 JSON 备份、显式确认后恢复演示数据。
- 编辑方向、增加行动、查看最近复盘。
- 为行动安排本地日期、时间和时长；已安排行动可导出为 `.ics`，再由用户手动导入日历。
- 设置日终回顾、每周复盘与专注块提前提醒；应用页面运行时检查，获得通知授权后可发送浏览器通知。
- 首页每日反馈按当日排期和任务状态显示已确认/待核实数量，并给出一项可执行的下一步。它是本地规则，不会把未记录的状态判为失败。
- 日终、周、双周和月末复盘会先显示对应排期区间的任务当前状态汇总，并对比区间内手动记录的结果指标变化；没有记录会如实说明，不替用户写结论或推断因果。
- 可选结果指标让你手动记录基线、目标和当前值，将长期职业/财务结果与每日行动进展分开查看；每次更新会保留本机历史记录并显示趋势图。
- 明确标示的本地演示建议，不声称已连接真实 AI。
- GitHub/项目板和 AI 服务仍显示为未连接；日历仅支持单向 `.ics` 导出，不连接或写入账户。

## 数据与限制

数据保存在当前浏览器的 `localStorage`（键名 `northstar-goal-monitor-v1`）。清除浏览器数据会删除记录；不同设备/浏览器之间不会同步。首页示例目标是可编辑的演示草案。

提醒偏好、排期和目标数据保存在当前浏览器的 `localStorage`。系统通知权限仅在用户点击“启用 / 检查系统通知权限”后申请；拒绝权限时仍显示应用内提醒。提醒调度只在应用页面运行时工作，页面关闭或浏览器节流时不保证触达。ICS 是用户触发的单向文件导出，不支持 OAuth、日历读写或实时同步。当前也没有真实账户登录、云同步、外部证据自动导入、真实 AI 服务或硬件连接。外部 Google Fonts 仅用于界面字体，离线时会回退到系统字体。
